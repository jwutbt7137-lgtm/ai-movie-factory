# 剪辑合成与导出（第四阶段）

当前版本：**v0.4.0**

第四阶段把「文案 + 配音时间轴 + 镜头方案」合成为可播放 MP4：逐句裁切镜头、补帧到配音槽位、拼接、混入配音/BGM、嵌入中文字幕，并保存 SRT/ASS 字幕。

## 1. 输入与前置条件

- 当前文案（`scripts` 当前版本）
- 当前配音（`voiceovers` 当前版本，基于同一文案）
- 当前镜头方案（`shot_matches` 当前版本，基于同一配音）
- 第一阶段镜头列表（序号/起止/时长）与源影片
- 可选 BGM 音频

导出前会校验：

- 配音的 `script_id` 必须等于当前文案；
- 镜头方案的 `voiceover_id`、`script_id` 必须等于当前配音/文案；
- 镜头方案必须覆盖当前配音的每一句；
- 镜头 ID 必须存在；
- 源影片、配音文件必须存在。

任何一项不匹配都会停止导出，不会悄悄用旧数据合成。

## 2. 合成流程

1. 读取配音每句的真实开始/结束时间。
2. 每句视频槽位 = 下一句开始 - 本句开始；最后一句槽位到配音总时长。
   - 槽位包含句后停顿，因此视频总长与完整配音一致。
3. 按镜头方案逐句裁切源影片：
   - 取镜头 `start_s` 到 `start_s + 需要时长`；
   - 统一 scale + pad（黑边）或 scale + center crop（中心裁切）到目标分辨率；
   - 统一 fps、SAR、yuv420p。
4. 每句镜头片段 concat；不足槽位时用最后一帧冻结（`tpad stop_mode=clone`）补足，超过则裁掉。
5. 每句输出一个临时 MP4（H.264，无音频），再用 concat demuxer 拼接。
6. 最终一步：
   - 画面：可选 ASS 烧录中文字幕；软字幕则把 SRT 作为 `mov_text` 轨嵌入；
   - 音频：完整配音 WAV；可选 BGM 循环并按固定 dB 压低，可再开人声 sidechain ducking，`amix` 后编码 AAC；
   - 输出 MP4，`+faststart`。
7. 同时保存 `.srt` 和 `.ass` 字幕；导出完成后清理临时片段。
8. 字幕三选一：ASS 烧录、SRT 软字幕轨、无字幕。

> FFmpeg 9 的 Windows 构建没有 `-filter_complex_script`，所以不是把 50 多个镜头塞进一条超长滤镜命令，而是先按句生成短滤镜图，再做最终合成。这样稳定、可定位错误，也不会撞 Windows 命令行长度限制。

## 3. 字幕

- 字幕文本来自配音句子（即最终 TTS 文案的切句）。
- SRT：通用格式，适合上传平台或后期导入。
- ASS：微软雅黑/可配置字体、白字黑边、底部居中、自动换行；导出时可选烧录。
- 字幕时间使用真实配音句时间；不会把整篇文案平均分配。
- 字幕只含 AI 解说文案，不包含原片对白。

三种模式：

| 模式 | 说明 |
|---|---|
| 烧录 | ASS 通过 libass 烧进画面，任何播放器可见；需要重新编码视频 |
| 软字幕 | SRT 作为 MP4 `mov_text` 字幕轨嵌入，默认轨，可开关/换字体；视频流直接 copy |
| 无字幕 | 不嵌入字幕；仍保存 SRT/ASS 边车文件 |

三种模式都会保存 SRT/ASS 边车文件。软字幕的播放器兼容性取决于目标播放器。

## 4. BGM 与音频

- BGM 可选，支持 mp3/wav/m4a/aac/flac/ogg。
- BGM 循环到成片时长，音量默认 -20 dB；UI 可调 -60..0 dB。
- 默认开启人声 sidechain ducking：人声出现时压缩 BGM；可关闭，改为固定 dB 混合。
- 没有多段音乐/淡入淡出编辑；BGM 太响时请降低 dB。
- 配音是完整 TTS 音轨（含句间/段间停顿），不会被重新加速。
- 输出 AAC 192k，48kHz 双声道。

## 5. 画面规格

| 选项 | 分辨率 |
|---|---|
| 横屏 1080p | 1920×1080 |
| 横屏 720p | 1280×720 |
| 竖屏 1080p | 1080×1920 |
| 方形 | 1080×1080 |

- 填充方式：黑边 pad（保留完整画面）或中心裁切 crop（铺满目标画面）。
- 没有主体跟踪智能裁切；竖屏/方形建议先人工看构图。
- 帧率 24/25/30/60。
- 编码 H.264；质量 CRF 18/20/23/28；preset slow/medium/veryfast/ultrafast。
- 没有画面裁剪、缩放构图、转场、花字、片头片尾；这些属于后续增强。

## 6. 手动换镜

镜头匹配页每行有「编辑镜头」：

1. 选中某句，点击「编辑镜头」。
2. 在全部镜头中勾选，按镜头序号顺序合成；显示已选总时长/目标时长。
3. 确认后生成新的 `ShotMatchPlan` 版本（保留旧方案），该句 `manual=True`、`needs_review=False`、置信度记为 1.0。
4. 其他自动句仍保留“需审核”；导出使用当前方案。

限制：只能按镜头序号顺序选择，不能拖拽重排、裁剪单镜头或加转场；选择时长不足时导出会用冻结帧补足，建议看一遍成片。

## 7. 进度与取消

- 逐句裁切阶段显示 5–60%；
- 最终合成阶段按 FFmpeg `out_time` 显示 65–97%；
- 取消会终止当前 FFmpeg 进程，删除未完成的输出；已完成的逐句临时片段会清理；
- 导出是 CPU 密集型任务，720p/3 分钟本次耗时约 51 秒。

## 9. 界面与命令行

界面：`剪辑合成` 页

- 画面/帧率/编码质量/黑边或裁切填充
- 字幕：烧录 / MP4 软字幕 / 无
- BGM 文件、音量、人声 sidechain ducking 开关
- 开始导出、取消、打开成片、打开字幕、导出目录
- 成片路径、时长、大小、上次导出信息

命令行：

```bat
run-cli.cmd export-video <PROJECT_ID> --out-dir exports --width 1280 --height 720 --fps 24 --crf 23 --preset veryfast --subtitle burn --bgm bgm.mp3 --bgm-volume-db -20
```

## 10. 已知限制

1. 镜头匹配仍是无视觉语义的启发式；必须人工审核/手动换镜。
2. 没有转场、花字、片头片尾；软字幕只有 SRT 文本，没有样式编辑。
3. BGM 有 sidechain ducking，但没有多段音乐/淡入淡出编辑。
4. 没有多轨道/多段工程时间线；每次按当前方案整体导出。
5. 竖屏/方形支持 pad/crop，但没有主体跟踪智能裁切。
6. 导出可能占用大量 CPU/磁盘；长片建议先用 720p/veryfast 试。
7. 成片仍需人工完整观看，检查镜头、字幕、音量、版权与平台规则。
