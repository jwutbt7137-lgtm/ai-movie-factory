# 配音与镜头匹配（第三阶段）

当前版本：**v0.4.0**

第三阶段目标：把解说文案变成逐句配音和句子时间轴，并为每句话选出一组候选镜头。第三阶段本身不导出视频；第四阶段已接入手动换镜、字幕和 MP4 合成，见 [`剪辑合成与导出.md`](剪辑合成与导出.md)。

## 1. 配音引擎

### Edge TTS（默认，免费在线）

- 依赖：`edge-tts>=7.0`（已加入 `requirements.txt`）
- 无需 API Key，无需注册
- 需要网络；文本会发送给 Microsoft 语音服务
- 支持中文普通话、粤语、台湾普通话等多种声音
- 支持语速、音量、音高
- 本项目使用 `edge-tts` 的非官方接口，服务可用性不保证；失败时会尝试回退

常用声音：

| 声音 ID | 说明 |
|---|---|
| `zh-CN-XiaoxiaoNeural` | 晓晓，女声，温柔自然（默认） |
| `zh-CN-YunxiNeural` | 云希，男声，年轻 |
| `zh-CN-YunjianNeural` | 云健，男声，有力 |
| `zh-CN-XiaoyiNeural` | 晓伊，女声，活泼 |
| `zh-CN-YunyangNeural` | 云扬，男声，播音 |
| `zh-CN-liaoning-XiaobeiNeural` | 晓北，东北女声 |
| `zh-CN-shaanxi-XiaoniNeural` | 晓妮，陕西女声 |
| `zh-HK-HiuMaanNeural` | 曉曼，粤语女声 |
| `zh-TW-HsiaoChenNeural` | 曉臻，台湾女声 |

### Piper（可选，完全本地）

```bat
.venv\Scripts\python.exe -m pip install "piper-tts>=1.8"
```

然后准备一个中文 Piper ONNX 模型（`.onnx` 与同名 `.onnx.json`），在「设置 → 配音与匹配 → Piper 模型」中填写 `.onnx` 路径。

注意：

- Piper 只负责推理，**不附带任何语音模型**。
- 中文 Piper 模型的训练数据许可各不相同；使用前必须自行确认模型/声音的许可，尤其不能把许可不明的模型随软件分发。
- 本项目开发机曾用 `zh_CN-huayan-medium` 做本地可用性验证，但该模型卡片的 Dataset License 标注为 **Unknown**，因此不随项目分发，也不建议直接商用。
- 本地引擎支持语速和音量；**音高只对 Edge 生效**，Piper 会忽略 pitch。

### 回退策略

- 「自动」：Piper 模型已配置且可用时优先本地，否则 Edge。
- 「Edge」/「Piper」：强制首选；主引擎失败且启用回退时，自动尝试另一个。
- 回退发生在逐句合成层；如果中途切换，完整音轨会混合两个引擎，`Voiceover.engine` 标记为 `mixed`，并写入警告。
- 两个引擎都不可用时直接报错，不会生成静音/假音频。

## 2. 句子切分与时间轴

1. 读取当前文案的段落。
2. 按 `。！？!?；;…` 切句；过长句再按 `，,、：:` 切分，仍过长则硬切（默认每句最多 80 字）。
3. 每句继承段落的剧情片段、对白证据、候选镜头和 `needs_review`。
4. 逐句合成音频，用 `ffprobe`/WAV 头读取真实时长。
5. 累加句间停顿和段间停顿：

```text
句 1: 00:00.000 → 00:05.376
停顿 250ms
句 2: 00:05.626 → 00:12.850
...
```

6. 按同一时间轴把逐句音频解码成 48kHz 单声道 PCM，插入静音，写出完整 `voiceover.wav`。

缓存：

- 每句音频的缓存键包含：引擎、声音、语速、音量、音高、文本。
- 相同文案/参数重跑直接复用，完整音轨仍会重新混音。
- 缓存位于 `projects/<项目>/voiceover/cache/`。
- 关闭「缓存」后不会复用已有逐句音频。

## 3. 镜头匹配

### 输入

- 当前文案（必须与当前配音的 `script_id` 一致）
- 当前配音的逐句时间轴
- 第一阶段镜头列表（序号、起止、时长、关键帧）
- 第二阶段剧情分析（段落关联的剧情片段和镜头编号）

### 规则

1. 候选镜头 = 段落关联镜头 ∪ 剧情片段镜头。
2. 从上一句结束的镜头之后开始，按镜头序号向后推进，避免每句都从头选。
3. 累加镜头时长，达到“配音时长 + 时长余量”后停止。
4. 候选镜头不够时，用紧邻的后续镜头补足；仍不够则标记“镜头总时长不足”。
5. 对镜头连续性（相邻编号比例）、时长覆盖、来源（段落/片段/兜底）计算规则置信度。

### 置信度的真实含义

当前**没有接入画面理解/视觉模型**，所以置信度只表示：

- 镜头是否来自文案关联的剧情片段；
- 时长是否覆盖配音；
- 镜头是否连续。

它**不表示画面内容与旁白语义一致**。因此：

- 未接入视觉语义时，置信度上限为 **0.70**；
- 所有镜头选择都标记 `needs_review=True`；
- UI 状态显示“25 句需审核”，不会把启发式结果说成“看懂了画面”。

第四阶段接入视觉描述/镜头语义后，才可能降低置信度或取消全量审核。当前也没有手动替换镜头界面。

## 4. 界面与命令行

### 配音页

- 选择引擎、Edge 声音、语速、音量、音高、停顿
- 「生成配音」在后台线程执行，可暂停/取消（暂停在句间检查点生效）
- 逐句表格：句号、开始、结束、时长、引擎、文本
- 选中行查看完整文本和关联片段/候选镜头
- 「打开配音文件」「配音目录」

### 镜头匹配页

- 「自动匹配镜头」要求当前文案与当前配音版本一致
- 表格：句、配音时间、目标时长、候选镜头、置信度、审核
- 选中行显示候选镜头关键帧、覆盖时长、原因
- 低置信度/未接入视觉时用黄色“需审核”标记

### CLI

```bat
run-cli.cmd tts <PROJECT_ID> --engine edge --voice zh-CN-XiaoxiaoNeural --out voiceover.wav
run-cli.cmd match <PROJECT_ID> --json
```

`tts` 会打印进度、总时长、音频路径、缓存状态；`match` 打印逐句镜头和置信度。

## 6. 已知限制

1. Edge TTS 需要网络，且是第三方非官方接口；服务中断时只能用本地 Piper 或其他引擎。
2. Piper 不附带模型；模型许可由使用者确认，音高不支持。
3. 多音字、专有名词、英文缩写、数字读法可能出错；必须试听。
4. 逐句合成会牺牲少量跨句语气连贯性；当前用停顿和统一声音缓解。
5. 镜头匹配无视觉语义，全部需人工审核；第四阶段提供逐句手动换镜，但仍不能裁切/拖拽/转场。
6. 配音/匹配不调用 DeepSeek，不增加 API 账单，但会产生本机 CPU/磁盘/网络开销。
7. 完整音轨是 WAV；第四阶段已可混音、烧字幕、导出 MP4，见 [`剪辑合成与导出.md`](剪辑合成与导出.md)。
